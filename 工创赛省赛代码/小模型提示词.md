# 怎么跟小模型说话（复制即用）

> 适用：本地离线模型（Ollama / llama.cpp / VS Code 插件等）。
> 原则：**一次一个任务、先让它复述规矩、只让它改一处、改完必须贴编译结果**。

---

## 0. 先做一次「能力自检」（只发一次，看它读没读文档）

```
你在接管一个 STM32 工程：D:\GoGoGo\hard_Update
先做两件事，不要改任何代码：
1) 读 规则.md（67 行）和 交接_给小模型_必读.md 的 §1 §2 §3（大概前 90 行）。
2) 然后回答我三个问题，每题一行：
   Q1 现在的 GO_TEST_FOLLOWSEQ 是多少？它代表什么？
   Q2 右基准的宏叫什么、在哪个文件？能不能动？
   Q3 你改完代码必须跑什么命令？必须看到什么输出？
```

**判读**：三题全对 → 可以派活；答错或答不出 → 说明它没读文件（见 §5 的「只会聊天」喂法）。

## 1. 开场（每次新会话第一句都用这段）

```
工程：D:\GoGoGo\hard_Update（STM32F407 + FreeRTOS，底盘机 + 手臂机各一个 20ms 状态机）。
规矩文件：规则.md（必读）；细节手册：交接_给小模型_必读.md（按需查，别整本读）。
硬约束（违反就要重做）：
1. 不许改我写的注释，过时了只指出来。
2. 能调的数用宏，不许改我给的数值。
3. 禁止三元表达式，一律 if/else。
4. 不要动 Go.c / pid.c / ins.c / hwt601.c / zdt_motor.c，要改先问我。
5. 右基准一律不许动（Follow.c 的 TF_PRE_GO_*_R、Follow.h 的 CELL_R*）。
6. 一次只改一处；拿不准就问我，给 2~3 个选项、推荐项放第一个。
7. 改完必须跑 bash _agent/build_verify.sh，并原样贴出最后一行
   BUILD CLEAN: 0 error / 0 warning (19 files)。没贴就当没改。
8. 报告格式固定：文件 → 函数 → 第几行 → 原值 → 新值 → 编译结果。
先不要动代码。确认你理解了以上 8 条，然后用一句话说明你现在要等我给什么。
```

## 2. 派活（模板，填空后发）

```
任务：<一句话说清要改什么>

定位建议：先 grep 关键字 "<关键字>"，只读目标函数前后 40 行，不要整文件读。
允许改的文件：<只列这一个/这几个>
不允许碰：右基准、框架 5 个文件、我的注释。

先给我【提案】，不要直接改：
【提案】
文件：
函数：
定位（grep 关键字/行号）：
现状代码：
打算改成：
为什么（一句话）：
会不会影响别的模块：
我回"执行"你才改。
```

### 常用任务的现成说法

**① 改一个数值**

```
任务：把 <宏名> 从 <旧值> 改成 <新值>，数值只改这一处，逻辑不动。
先告诉我它在哪个文件第几行（用 grep 找），再给我提案。
```

**② 改抓取判定（最容易改错）**

```
任务：我想调整抓取成功判定。先只做一件事：把当前判定的完整链路给我讲清楚——
Grab.c 的 case 3 子步 4 怎么取帧（gb_capture_chk）→ See.c 的 See_RecentColorsSince 怎么填数组
→ 最后怎么数命中。不要改代码，讲完等我确认。参考：手册 §5.2、§7、§11。
```

**③ 加一个开关**

```
任务：新增一个开关 <名字>，1 = <新行为>，0 = <原行为>。
照 交接_给小模型_必读.md §26.2 模板 B 的四步做（宏+const / extern / if-else / 更新 §3.2 表）。
先给提案。
```

**④ 单独测抓取**

```
任务：我要用 grab0 单独测抓取。先按 交接_给小模型_必读.md §25 告诉我：
要改哪两个地方、Set(...) 那 12 个参数怎么填、跑起来会发生什么、出问题怎么查。先别改，我要核对。
```

## 3. 它想越界时，三句现成的话

| 它想干什么 | 你回什么 |
|---|---|
| 顺手「优化」别的代码 | 停。只改我指定的那一处，其它一行都不要动。把刚才多改的地方还原。 |
| 改框架文件 / 右基准 | 那两个是禁区（规则.md 红线 4、5）。撤销，改成在允许的文件里实现；做不到就停下来告诉我为什么。 |
| 改了我的注释 / 想重写注释 | 我的注释不许改。你只可以在旁边新增一行说明，或者直接告诉我它过时了。撤销。 |
| 写三元表达式 | 改写成 if / else，不要三元。 |
| 编了不存在的函数/行号 | 不要凭记忆。用 grep 找出来，把真实那一行原样贴给我，再继续。 |

## 4. 验收（每次它说「改好了」你都发这段）

```
按格式报告，缺一项我都不接受：
1. 改了哪个文件、哪个函数、第几行
2. 改之前的代码（原样贴）
3. 改之后的代码（原样贴）
4. bash _agent/build_verify.sh 的最后一行输出（原样贴）
5. 如果没跑或没通过，直说没通过，不要解释成"应该没问题"
```

它说「改好了」但没贴 BUILD CLEAN 时，只回一句：

```
没贴编译结果 = 没改。现在跑 bash _agent/build_verify.sh，把最后一行原样贴给我。
```

## 5. 两种运行时的喂法

### A. 它能读文件（Cline / Roo Code / Continue / Agent 模式）

- 只给它目录 + 规矩文件名，让它自己 grep。
- 要求它每次只读「目标函数 ±40 行」，禁止整文件贴进上下文（它上下文很小）。
- 让它把 grep 结果贴出来，你再判断它找对没有。

### B. 它只能聊天（纯 Ollama / 网页式）

- **你自己 grep**，只把必要片段贴给它：① 目标函数完整那一段（±40 行）② 用到的宏定义（grep -n 宏名 的结果）③ 相关头文件里的声明。
- 贴的时候加一句：

```
下面是全部相关内容，除此之外不要假设代码里还有别的东西。找不到的信息就说"信息不足"，不要猜。
```

- 一次只贴一个函数。想改流程时，再补 规则.md 第三节的当前状态表。

## 6. 别做的事

1. **别一次给多个任务** —— 弱模型会做一半就串了。
2. **别说「顺便看看有没有别的问题」** —— 它会开始重构。
3. **别贴整个文件** —— 它的上下文会被挤掉，反而读不准。
4. **别信它没跑编译的「应该没问题」** —— 只有 BUILD CLEAN 才算。
5. **别让它自己决定宏名/新数值** —— 可以让它给建议，最后你定。

---

## 7. 一句话总结

**先读规则 → 只提一处 → 先要提案 → 你点头再改 → 必须贴 BUILD CLEAN → 报告五要素。**
