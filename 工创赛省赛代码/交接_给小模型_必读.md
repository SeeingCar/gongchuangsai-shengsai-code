## 0. 三句话搞清这个工程

1. STM32F407 双机工程（FreeRTOS）。**底盘**（`GroundFloor/`）+ **手臂**（`Grab/`）各一个状态机，跑同一个 20ms 节拍（`CTRL_DT_MS = 20`，`chassis_cfg.h` 18 行）。
2. 比赛任务：底盘按二维码给的路线跑 + 巡逻找料 → 手臂跟踪、判停、抓三块 → 找 8 号环、对 7/9 号环标定、放料。
3. 两台机靠 4 个 int 变量握手：`grab_allow` / `grab_id_done` / `grab_round2` / `grab_round3`。

| 环节 | 正常流程（`grab0 = 0`） | `grab0 = 1` |

⚠ 只在 `GO_TEST_FOLLOWSEQ = 0`（正常分支）里生效；台架支（= 1）根本到不了这里。
⚠ 抓取成功判定的逻辑一点没变，V 行照旧每 5s 打一次，三块抓完停发。

### 5.2 `blue_merge_key` 的真实语义（容易理解错）

它**不是**"1 = 3 和 6 永远同色"。真正生效条件在 `See.c` 456-468：

| `blue_merge_key` | 三块料里 3、6 是否都出现 | 结果 |
|---|---|---|
| 0 | 任意 | 严格区分 3 / 6 |
| 1 | 没同时出现 | **3 ≡ 6**（跟踪、判定、剔除全生效） |
| 1 | 同时出现 | 严格区分 |

所有颜色判等都必须走 `See_SameColor(a,b)`，**不要用 `==` 比颜色**（会绕过合并）。

### 5.3 抓取高度（`high`）

`high` = **实测的放料盘高度 cm**，现在 `9.4f`。

抓取时 UD 的目标高度（= 下降量，0 = 顶）：

```
ud_cm = 5.15 - (high - 8)          /* 在 Grab.c 827 / 835 行 */
```

| high | ud_cm |
|---|---|
| 8.0（基准） | 5.15 |
| 9.0 | 4.15 |
| **9.4（当前）** | **3.75** |

⚠ `ud_cm` **越小 = 手臂抬得越高**。盘高每 +1cm，抓取位置就上抬 1cm。

## 6. 两台机的流程

### 6.1 底盘 `TaskFlow_Update()`（`TaskFlow.c` 434 行 `switch (Go_now)`）

| case | 干什么 |
|---|---|
| -1 | 跑任务1 路线 + 扫码 + 去 15 号格 |
| 0 | 摆位/与手臂交接 |
| 1 | 巡逻找料 |
| 2 | 跟踪物料 |
| 3 | 手臂抓取期间底盘原地不动 |
| 4 | 三块抓完 → 去 23 号格 → 跑任务3 → case 5 |
| 5 | 找 8 号环（第一轮用跟随轴，第二轮用反轴） |
| 6 | 底盘停 → case 7 |
| 7 | 放料（底盘停）。手臂进收工位后分三路：`big_round != 0` → **case 10 停**；`s_ring_round == 0` → case 8；否则 → case 9 |
| 8 | 去 3 号格 + 跑任务4；8-2 走完：`big_round != 0` → case 10；`s_ring_round == 0` → 回 case 5；否则停 |
| 9 | 去 11 号格 + 跑任务5 → `big_round = 1`、`Grab_UseRound2()` → case 1（第二遍开始） |
| 10 | `GO_Stop()` 停住 |
| 11 | 第二遍第二次的图像对准 —— **现在不做** |
| 12 | 第二遍第二次的放料 —— **现在不做** |

两个轮次标志：`big_round`（0 = 第一遍，1 = 第二遍）、`s_ring_round`（0 = 本轮第一次找环，1 = 第二次）。

**当前流程（2026-11-05 改后）：**
- 第一遍：抓三块 → 找环 → 放料（轮1）→ case 8 → 回 case 5 找环 → 放料（轮2）→ case 9 → 第二遍
- 第二遍：抓三块 → 找环 → 放料（轮1）→ **case 10 原地收工停住**（不再做第二轮放料 11/12）

## 9. 已知陷阱（踩过的，务必先看）

1. **Keil 旧缓冲区会覆盖磁盘**：用户在 Keil 里编辑，改完要 `File → Reload`。判断"磁盘到底改没改"的唯一可靠办法 = **跑一次 `build_verify.sh`**，别信 Keil 里看到的内容。文件被外部改过时，编辑工具会报 `file changed since it was read`，此时**先重新读文件再改**。
2. **宏不能跨 .c 文件**：在 `freertos.c` 写 `#define x 5`，`Grab.c` 里 `x` 会编不过。跨文件要按用户惯例：`#define` + `const T g_xxx = ...;` 在 `freertos.c`，`extern const T g_xxx;` 放头文件（例子：`g_high`、`g_case11_key`）。
3. **没有 case 13**：`switch (Go_now)` 只有 -1、0~12；`switch (Grab_now)` 只有 0~12；两者**外层都没有 default**。写 `Go_now = 13` = 两个状态机同时静默冻结（不调 `GO_Stop()`、不保持力矩），现场表现就是"车不动了"。
4. `s_gb_ts`（`Grab.c` 53 行）**一个变量被多处复用**（抬升计时 / 采样窗口起点 / 各种超时基准）。改采样逻辑前先确认那一刻它是哪个含义。
5. `s_chk_col[grab_id][i]` 会越界（第 3 块抓完 `grab_id = GRAB_ROUNDS`）。现有保护 `if (grab_id < GRAB_ROUNDS)` **别删**。
6. `GO_SetTaskPos()` **只平移位姿、不改已下发的目标**。调用后必须紧跟 `GO_Stop()` 或 `GO_To()`，否则控制器会拿新位姿去追旧目标。
7. 到位判据是**径向**死区 `sqrt(ex²+ey²) <= GO_TOL_XY_CM(0.5)`。差 4cm 绝不可能是死区吃掉的。
8. 里程计是**驱动器实测多圈角度**积分（`freertos.c` 282-299 → `ins.c` 52-53），"车以为到了"= 轮子真转了那么多圈；实测比它短 ⇒ 真实打滑。
9. `Follow.c` 的路线拆分：`task == 1 && i == 1` 和 `c == 13` 时会拆成"先走位置、再原地转"两段。
10. 用户靠**实物现象**验收（会拿卷尺量），改动要给出能对数的串口打印。

## 16. 坐标系与"下目标"的三种方式

- **任务系**：`GO_Home()`（在 `Motion_Home` 里）把**停车那一刻的车头**锁成 `+X`，左手边为 `+Y`，`yaw0` = 那一刻的 IMU 角。格号坐标表 `CELL_L*` / `CELL_R*` 都是这个系下的 cm。
- 所有执行器的量都是**绝对量**：6020 的 deg = 编码器绝对角；M2/M7 的 cm = 从驱动器零点算起的绝对量。

| 函数 | 语义 | 注意 |
|---|---|---|
| `GO_To(x, y, dyaw)` | 任务系**绝对**位置 + **相对**朝向（`dyaw` 加到**当前目标朝向**上，0 = 不转） | 目标一改，`GO_Arrived()` 立刻变 0 |
| `GO_Stop()` | 目标冻在当前位姿 + 强制出零速度 | 每拍都要调才稳 |
| `GO_SetTaskPos(axis, v)` | 强行把任务系坐标改成 `v`（1=X / 2=Y，另一轴不动） | **只改位姿不改目标** ⇒ 必须紧跟 `GO_Stop()` 或 `GO_To()` |
| `GO_SetVmax(v)` | 平移速度上限 cm/s（`<=0` 恢复默认档） | 只压上限，不改刹车包线 |
| `GO_SetTol(xy)` | 改到位死区 cm（默认 `GO_TOL_XY_CM 0.5`，最小 0.05） | 跟踪用细死区 `GO_TOL_XY_FINE_CM 0.05` |

## 18. 执行器语义

## 19. 抓取策略：这是"可行性判断"，不是"看到就抓"

看到目标色之后**不能立刻停**，要先判"这个位置能不能抓"，否则会夹空 / 顶限位 / 来回震荡。

判停（A1）的全部条件（`Grab.c` case 2，758-783 行）：

| 条件 | 量 |
|---|---|
| 纵向跟得上 | `|e_cm| <= tol_cm`（基准已定）或 M2<16cm 时用宽死区 |
| 横向进 A1 门 | `|cam_cx - cam_grip_cx_px| <= A1_CX_TOL_PX(18)`（基准未定时用 `TF_FIRST_TOL_PX 30`） |
| 手臂停住 | `|v_arm| <= GB_STOP_V_CMPS` 且 `|v| <= GB_STOP_V_CMPS` |
| 判基准阶段额外要求车也停 | `|TaskFlow_CarV()| <= TF_BASE_V_CMPS(2.5)` |
| 连续帧数 | 以上全满足连续 `STOP_CONFIRM_FRAMES(2)` 帧 → `grab_allow = 1` |

- **M2 长度阈值**：`TF_M2_GRAB_CM 9.0f`（可抓阈值，M2 比它短才抓得到）。
- **基准（base）**：第一次判停时记下底盘 X / M2 长度，后面用它判断"车是不是够得着"；第二遍开始会清 `s_base_shot = 0` 重新采样（`TaskFlow.c` case 9-2）。
- 兜底：够不着时（顶在软限位且 `|cy| > 41px` 连续 `GB_STUCK_MS`）会回 case 1 重新找机会。

## 21. 血泪教训（会直接影响你要做的事）

1. **CubeMX 重新生成会清掉 USER CODE 区之外的一切**：历史上 `uart1_send` 整个函数和 `s_route_halt` 被清掉过（8 warning + 1 error）。

2. **Keil 的旧缓冲区会覆盖磁盘**：判断"磁盘到底改没改"的唯一可靠办法 = 跑一次 `build_verify.sh`，别信 Keil 里看到的。
   ⇒ 编辑工具报 `file changed since it was read` 时，**先重新读文件再改**。
3. **脚本批量删代码极危险**：曾按"从 A 到下一个 `}`"删死代码，把 `See_Init()` 和 ISR 的 8 个静态变量一起删了，编译不报、**链接**才报 `L6218E`。
   ⇒ 删除只用精确锚点，删完 `diff` 逐行确认。
4. **写文件必须 UTF-8**（中文注释/输出），否则 GBK 控制台报 UnicodeEncodeError。
5. 用户偏好：中文**简短**注释、只解释"为什么"；**新增的、要现场调的数要做成宏**，但他已经写死的数值**不要**为了好看改成宏（两条不矛盾：§1 第 2 条指的是"你要改的那个数"）。

### 25.3 为什么闸门要反过来（最容易改错的地方）

两个阀门是**互锁**的，每个状态机第一行就是门锁：

| 状态机 | 门锁 | 谁能开它 |
|---|---|---|
| 手臂 `GRAB_Update()` | `if (!grab_gate) return;`（`Grab.c` 494 行） | StartTask / 底盘 `case 0`（`TaskFlow.c` 490 行）|
| 底盘 `TaskFlow_Update()` | `if (!tf_gate) return;`（`TaskFlow.c` 432 行） | **只有 StartTask 和手臂 `case 0`（`Grab.c` 509 行）** |

正常流程：StartTask 放底盘 → 底盘跑 `case -1`/`case 0` → `case 0` 开 `grab_gate` 关 `tf_gate` → 手臂摆位 → 手臂 `case 0` 重开 `tf_gate` → 底盘进 `case 1`。
grab0 流程：跳过前段 → 所以**必须由 StartTask 直接开手臂、关底盘**，让手臂摆位后自己重开 `tf_gate`。这就是 `tf_gate = 0; grab_gate = 1;` 的原因。

> 反过来写（`tf_gate = 1; grab_gate = 0;`）会怎样：底盘在 `case 1` 开始巡逻，但手臂一直被门锁挡着不动 ⇒ 永远抓不到。

## 26. 改代码的套路（4 个模板，照抄结构就不会错）

> 这四个模板覆盖了本工程 90% 的改动。**不要发明新写法**，照模板来。

### 26.1 模板 A：改一个阈值

1. `grep -n 宏名` 找到定义处（通常在 `grab_cfg.h` / `chassis_cfg.h` / `freertos.c` 开关区）。
2. **只改数值**，不改名字、不改格式。
3. `bash _agent/build_verify.sh` → 必须 `BUILD CLEAN: 0 error / 0 warning (19 files)`。
4. 报告：文件 → 宏名 → 旧值 → 新值 → 编译结果。

⚠ 如果这个数**没有宏**（例如抓取判定里的 `500`、`> 2`），先告诉用户"这里没有宏，要我做成宏吗"，**不要直接改裸数字**。

### 26.2 模板 B：加一个开关（本工程固定 4 处）

```c
/* ① freertos.c 开关区：宏 + const */
#define xxx_key             0
const uint8_t g_xxx_key = (uint8_t)xxx_key;

/* ② 某个头文件（TaskFlow.h / See.h / grab_cfg.h）：跨文件声明 */
extern const uint8_t g_xxx_key;

/* ③ 使用点：if / else 直白展开（禁止三元表达式）*/
if (g_xxx_key != 0) {
    /* 新行为 */
} else {
    /* 原行为 */
}

/* ④ 更新交接手册 §3.2 的开关表 */
```

### 26.3 模板 C：加一个 case 的子步（子状态机）

```c
case N:   /* 这一步干什么 */
    switch (s_sub) {

    case 0:   /* N-0 下发指令：**只发一次** */
        if (!s_sent) {
            MoveCm(...);                 /* 或 GO_To(...) */
            s_gb_ts = HAL_GetTick();
            s_sent  = 1;
            break;                       /* 发完先返回，下一拍再判到位 */
        }
        if (!M27_UdArrived()) break;     /* 等到位；没有反馈就一直等 */
        s_sent  = 0;
        s_sub   = 1;
        break;

    case 1:   /* N-1 收尾：清标志、交接、进下一步 */
        Grab_now = N + 1;
        grab_id_done = 1;                /* 通知另一台机 */
        break;
    }
    break;
```

三条硬纪律：
1. **指令一拍只发一次**（用 `s_sent`），每拍重发会丢帧。
2. **等不到反馈要有兜底**（`HAL_GetTick()` 超时），否则整局卡死。
3. **退出路径必须成对清标志**（`grab_allow` / `grab_gate` / `s_sent` / `grab_id_done`），否则下一轮会误用旧值。

### 26.4 模板 D：加一个台架测试

1. `Test/Go_Test/go_test.c` 里加函数，**所有可调数写成宏**，结构照抄 `Go_Test_OdoRun`：
   先 `Motion_Home()`（10s 兜底）→ 打 `X,BEGIN` → 下发 → 每 200ms 打一行 → 到位打 `X,DONE` → 之后每秒打位姿。
2. `Test/Go_Test/go_test.h` 加声明。
3. `Core/Src/freertos.c`：

   ```c
   #define GO_TEST_FOLLOWSEQ   1     /* 1 = 台架支 */
   ...
   519 行：Go_Test_你的函数();
   ```
4. 编译 + 上机，让用户拿卷尺量；跑完把 `GO_TEST_FOLLOWSEQ` 改回 `0`。
