## 一、十条红线（违反任何一条，用户会要求重做）

1. **不许改用户写的注释** —— 过时了只**指出来**，绝不自己改。
2. 能调的数做成宏；**不许改用户给定的数值**。
3. **禁止三元表达式** `a ? b : c` —— 一律 `if / else`。
4. **不许动框架**：`Go.c` / `pid.c` / `ins.c` / `hwt601.c` / `zdt_motor.c`，要改先问。
5. **右基准一律不许动**：`Follow.c` 的 `TF_PRE_GO_*_R`、`Follow.h` 的 `CELL_R*`。当前只调左基准。
6. 缩进 4 空格（原文件是 TAB 就保持 TAB）；注释中文 `/* */`。
7. 命名：文件内 static 用 `s_xxx`；对外共享用裸名字（`Grab_now` / `Go_now` / `big_round` / `grab_id` / `cam_target_id`）。
8. **拿不准就问**，给 2~3 个选项、推荐项放第一个，不要猜。
9. 一次只改一处；改完**必须报告**：文件 → 函数 → 第几行 → 原值 → 新值 → 编译结果。
10. 只做用户要求的那一处，不要顺手重构。

## 二、验收（每次改完必须跑）

```bash
bash _agent/build_verify.sh
```

必须**原样**打出：

```
BUILD CLEAN: 0 error / 0 warning (19 files)
```

多一个 warning 就算失败。这个脚本调的就是**真编译器** `D:\keil5\ARM\ARMCC\bin\armcc.exe`（本机没有 gcc）。

## 四、三条协作协议

1. **一次只改一处**；改完必须贴出上面那行 `BUILD CLEAN`，没贴就当没改。
2. **先提案再动手**：先说"改哪个文件哪个函数、为什么、影响谁"，用户点头才改。
3. 你八成会犯的错只有三类：**① 动右基准 ② 写不存在的 `case 13` ③ 改用户注释**。
   每个提示词开头把这三条重复一遍，收益最大。
